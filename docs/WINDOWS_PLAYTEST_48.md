2026-09-11. 진행 현황의 **3·4단계(차량·전체 배송·성공/실패/평가)**를 통합한 Windows 테스트 빌드. 최종 실행 파일 자동 검사 662개를 통과했다. 기존 미커밋 작업을 유지했고 커밋/push는 하지 않았다.

## 이번 플레이

메인 메뉴의 **전체 배송 · 적재 / 운전 / 빌라 · 1~4인** → 방 만들기 또는 같은 모드 IP 참가 → 주문/캐릭터 선택 → 전원 준비 → 배송 시작.

물류센터의 택배를 직접 잡아 열린 트럭 뒤 경사로로 싣고, 옆으로 비켜서 E로 문을 닫는다. 가까이에서 F로 탑승하며 첫 탑승자가 운전석이다. WASD로 약 60m 앞 빌라까지 운전하고 노란 주차 구역에 정차한다. F 하차 → E 문 열기 → 직접 하역 → 기존 왼쪽 골목/실내 계단을 따라 2층 201·202호에 배송한다. 결과에서 같은 주문 재시작 또는 대기실의 다음 주문/코스로 이어진다.

기존 빌라 연습/싱글/로컬 분할 화면은 별도 메뉴로 유지한다. 전체 배송의 차량·평가 규칙은 새 모드에만 적용한다. 45kg 공동 택배는 두 사람 이상 운반을 전제로 한다.

## 구현

- 기존 Kenney delivery 차량 모델, 캐릭터, 공장 택배/상자 에셋을 사용한 물류센터와 기존 빌라의 연속 지면/도로.
- 힘으로 가속·후진·제동하는 RigidBody 차량 1종, 4개 좌석, 운전자 교대, 차량 카메라와 엔진음. 차체의 좌우/앞뒤 기울기는 잠근 아케이드 프로토타입이다.
- F 탑승·하차, 정차한 트럭 뒤 E 문/경사로. 움직일 때 조작 거부, 문 주변 물건/사람 보호, 하차 공간 검사와 동시 하차 위치 분리.
- 택배는 차량의 자식으로 고정하지 않는 독립 물리 물체. 실제 화물칸 적재 이력을 기록하며 닫힌 문은 화물을 막고 열린 문은 낙하를 허용한다.
- 호스트가 차량/좌석/문/화물/손상/시간/평가를 판정. 20Hz 차량·배송 상태 패킷을 기존 플레이어/물체 패킷과 분리해 다건 4인에서도 MTU를 넘지 않게 한다. 프로토콜 48, 모드 불일치 거부.
- 메뉴/운전자 입력 지연은 가속을 해제하고 제동한다. 하차 시 충돌을 즉시 재활성화해 발생하던 비정상 충격을 방지한다.
- 배송은 적재 확인 + 빌라 주차 + 올바른 주소 + 파손/분실 아님을 요구한다. 목표 수는 기존 주문 정의와 배송 구역을 공유한다.
- 상태 0 택배는 파손, 맵 아래로 떨어진 택배는 분실. 일부 배송 후 나머지가 실패하면 부분 결과, 제한 초과/차량 상태 0도 종료한다. 결과는 S/A/B/C/F와 점수 및 사유를 표시하고 방의 최근 기록에 남는다.
- F5 전체 복구는 완료/실패 판정·택배/차량 상태를 유지하며 1회당 50점 감점한다. 개인 복구는 자기 위치만 옮긴다. R 재시작은 새로운 주문 상태를 만든다.
- 설정 없는 첫 실행에서도 기본 캐릭터를 보장한다. 새 자동 검사 설정은 검사 폴더로 분리한다.

## 조정 가능한 평가 기준

일반 8분, 다건/공동 12분, 혼합 11분. 택배/차량 상태는 100부터 시작한다. 택배는 한 물리 프레임의 합산 충격량/질량이 3.5를 넘을 때 초과분 ×8 손상, 0.4초 중복 방지. 차량은 수평 합산 충격량/질량 2.5 초과분 ×8, 0.5초 중복 방지. 복구 순간에는 충격을 계산하지 않는다.

점수 = 배송 비율×700 + 배송 택배의 상태 합/목표 수×2 + 남은 시간 비율×100 − 차량 손상 − 전체 복구×50 + 공동 잡기 보너스 20. 성공은 0~1000, 실패는 최대 599점. 배송 0개는 0점/F, 전량 성공 900 이상 S/750 이상 A/550 이상 B, 그 외 C. 성공은 제한 시각 **이전**에 전량 배송하고 차량 상태가 0보다 커야 한다. 전량 배송도 시간 마감/차량 파손을 무효화하지 않는다. 영구 화폐·구매·해금·저장은 포함하지 않는다.
