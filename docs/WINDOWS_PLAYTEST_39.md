## 변경
온라인 배송 중 창 포커스를 잃으면 내 메뉴를 열고 이동·잡기·점프·달리기 액션을 초기화한다. 메뉴 중 전송되는 중립 입력으로 호스트의 권한 시뮬레이션에서도 참가자 입력을 멈춘다. 잡은 택배는 놓으며 상대의 배송과 연결은 계속된다.

창으로 돌아와도 자동으로 재개하지 않는다. 계속하기 또는 Esc로 재개하며 이전 입력을 다시 초기화한다. 포커스가 없는 동안 재개 요청은 무시한다. 로딩 중 창을 벗어나면 로딩 완료 후 메뉴를 표시한다. 이미 열려 있는 설정/조작 안내나 완료 화면은 창 전환 때문에 닫지 않는다. 접속·로비 상태와 준비 상태는 유지한다.

Window focus_exited/focus_entered 신호를 사용한다. 네트워크 패킷 형식과 프로토콜 37, 맵, 물리 수치는 유지한다. commit/push 없음.

## 검증 방법과 한계
두 Windows 테스트 프로세스가 데스크톱 포커스를 경쟁하므로 자동 드라이버에서 실제 창 포커스 신호 연결을 해제하고 같은 콜백을 명시 호출한다. 따라서 이 검사는 입력/메뉴/네트워크 상태 검증이며 실제 Alt+Tab 또는 최소화 조작 통과를 뜻하지 않는다. 호스트·참가자 각각 포커스 손실 시 로컬 입력 중단, 상대 이동 유지, 복귀 후 명시 재개를 검사한다.

기존 배송 운반·설정·로비·재참가·로딩 중 끊김 회귀도 수행한다. 202호 운반은 합성 입력, 초기 위치 배치와 최종 201호 배송은 fixture다. 외부망·장시간 실제 플레이는 미검증이다.

## 사용자 확인
이동하거나 택배를 잡은 채 Alt+Tab 또는 최소화 → 상대 화면에서 내 이동/잡기가 중단되는지 확인한다. 돌아온 뒤 메뉴가 유지되고 계속하기 또는 Esc로 재개되는지, 상대는 계속 배송할 수 있는지 확인한다. 로딩 중 창 전환도 확인 대상으로 남긴다.

첫 NetworkFinal에서는 상대 이동 검사 위치가 이전 동선의 트럭 주변에 남아 이동 거리 조건을 충족하지 못했다. 포커스 검사를 열린 바닥의 별도 초기 위치로 분리했으며 NetworkVerified에서 해당 검사는 통과했다. 같은 첫 실행에서 202호 상자가 상부 계단 운반 도중 해제되어 배송 완료와 후속 로비 검사가 연쇄 실패했다. 물리 수치나 운반 코드는 변경하지 않았으며 이 운반 해제는 미해결 재현 관찰로 남긴다. 첫 실패 로그는 validation/villa-39/NetworkFinal에 보존한다.

메뉴/설정/조작 안내/완료 화면에서는 배송 HUD를 숨기고 재개 시 복원해 호스트 메뉴 제목과 진행 표시의 겹침도 수정했다.
