# Windows 플레이 테스트 26 — 온라인 2인 빌라

2026-09-11-villa-26 · Windows x86_64 · Godot 4.7.1 debug export

## 승인 및 범위

사용자가 현재 빌라 온라인 2인 제안에 고고로 승인했다. 방 만들기/IP 직접 참가, 캐릭터 이동/시점/모션, 택배 공동 운반, 201/202 배송, 완료/복구/재시작, 양방향 연결 종료와 재접속을 구현한다. 이전 온라인 제외 규칙은 이번 명시 승인 범위에 적용하지 않는다. Steam 초대/중계/차량/원격 push/공개 배포는 제외한다. 미커밋 작업과 이전 빌드 보존.

## 구현 구조

- OnlineSession 전용 씬의 RPC 노드 경로를 양쪽에서 동일하게 유지한다. 전역 Autoload 추가 없음. MainMenu에 온라인 버튼 추가.
- OnlineLevel은 현재 VillaCoopLevel을 재사용하되 전체 SceneTree를 멈추는 로컬 완료 UI를 사용하지 않는다. 2인이 준비된 뒤 호스트만 물리/배송을 계산한다.
- Player.NETWORK는 호스트에서 검증된 입력을 물리 프레임에 적용한다. 입력 벡터/시점 유한값·범위·송신자·세대 검사. 입력 중단 0.5초 후 중립 입력으로 정지한다.
- 패킷에서 시점 변경과 잡기가 동시에 들어오는 경우 ShapeCast를 현재 시점으로 갱신한다. 이 수정으로 이전 시점 판정에 따른 공동 잡기 실패를 해결했다.
- 참가자는 이동/시점/잡기/점프/달리기 입력을 보내고 20Hz 호스트 상태를 받아 위치를 보간한다. 양쪽 모션/머리/운반 포즈와 캐릭터 선택값 반영.
- 참가자 RigidBody는 freeze, 배송 Area는 monitoring=false. 상태 패킷으로 배송 수/표시/택배 표시 여부를 반영한다. 완료는 reliable로 보내며 오래된 상태 패킷이 완료 수를 되돌리지 않는다.
- 재시작마다 세대 번호와 월드를 갱신한다. 복구는 완료한 배송 유지. 메뉴는 상대의 게임을 정지시키지 않고 자기 입력을 중립화한다. 복구/재시작은 호스트 전용.
- 기본 UDP 27926(접속 화면에서 변경 가능), 최대 참가자 1명. 프로토콜 버전 일치 필요. IP 입력 검증, 접속 10초 제한, 연결 종료/응답 중단 안내와 월드/peer 정리, 같은 프로세스 재접속.
- 참가자 동작 소리는 호스트의 속도/접지/운반 상태에서 재생한다. 배송 소리는 공통이며 거리 기반 공간 음향은 아직 없다.

## 검증 구분

Run-OnlineTest.ps1은 실제로 별도 Windows 게임 프로세스 두 개를 시작한다. loopback ENet 접속으로 이동/시점/공동 잡기/한 사람 놓기/참가자 계단 운반/부분 복구/완료/재시작/참가자 종료/재접속/호스트 종료를 검사한다.
공동 잡기 초기 배치와 마지막 201호 배송은 host fixture다. 202호는 참가자 합성 입력이 네트워크를 거쳐 실제 계단을 운반한다. 두 집 모두 사람 손으로 플레이한 검증은 아니다.
초기 검사에서 타입 추론 오류, 엔진/수동 보간 중복 경고, 동일 패킷 시점/잡기 탐색 오류를 수정했다. 빠른 자동 회전이 상자를 계단 모서리에 걸리게 한 경우는 실제 안전 놓기이며, 입력 경로를 천천히 이동/모서리 정지 방식으로 조정했다. 실패·중단 기록은 validation/villa-26의 Source*/NetworkFinal* 폴더에 보존하고 최종 통과 로그와 구분한다.

## 알려진 한계

- 실제 두 PC LAN/외부 인터넷, Wi-Fi 지연/손실, 장시간, 실물 패드 테스트 미완료. 이 온라인 빌드는 각 PC 키보드·마우스 기준이다.
- 참가자 위치는 호스트 응답 기반 보간이며 로컬 이동 예측/재조정은 없다. 지연이 큰 연결에서는 이동·운반 반응이 늦을 수 있다.
- 직접 IP 접속이며 Steam 친구 초대/릴레이/NAT 자동 통과/호스트 이전은 없다. 인터넷 직접 연결에는 호스트 쪽 UDP 포트 접근 가능 설정이 필요하다.
- 진행은 세션 한정이며 연결 종료 후 새 방은 처음부터 시작한다.
- 기존 두 집/캐릭터/에셋/물리 규칙을 사용하며 공개 배포용 보안/호환성 검증 완료를 뜻하지 않는다.
