# Windows 테스트 빌드 47 — 빌라 협동 기준선과 온라인 4인

2026-09-11. 사용자 승인: 진행 현황의 빌라 협동 기준선 확인과 온라인 기반 확장을 한 묶음으로 진행. 차량·경제·Steam 배포는 이번 범위가 아니다. 기존 미커밋 작업을 보존하며 commit/push 없음.

## 구현

- 온라인 방 정원 2~4명. 네 개의 캐릭터 미리보기와 독립 선택/준비, 현재 참가자 전원이 준비했을 때만 출발한다. 비어 있는 자리는 준비/완료 동의 대상에서 제외한다.
- 호스트가 네 플레이어의 입력·이동·물리 공동 잡기·택배·배송 판정을 관리한다. 참가자는 자기 슬롯의 시점과 입력을 사용하고 나머지는 호스트 상태를 받는다. 빈 슬롯은 캐릭터와 충돌을 비활성화한다.
- 참가자별 입력 시각을 관리하여 0.5초 이상 입력이 끊기면 해당 인물만 정지시킨다. 호스트 HUD에 지연된 P번호를 표시한다.
- P1~P4 운반 현황/동료 표식/운반 도움 요청, 각자의 개인 복구, 현재 참가자 전원의 부분 종료 동의, 네 가지 주문과 3연속 코스를 연결한다.
- 대기실 퇴장 시 남은 방과 리스너를 유지하고 준비를 해제한다. 배송 중 퇴장 시 남은 전원을 대기실로 복귀시켜 현재 주문을 다시 준비한다. 완료한 이전 코스 실적은 유지한다. 빈 슬롯에 재참가할 수 있다. 호스트 이전 기능은 없다.
- 배송 중 새 참가와 다른 프로토콜은 사유를 표시하고 거절한다. 로비 승인까지 접속 제한 시간을 유지해 대기가 끝나지 않는 상황을 막는다. 프로토콜 47, 모두 같은 빌드를 사용해야 한다.
- 계단 운반 반복에서 두 종류의 잡기 해제를 재현했다. 계단 접촉으로 잡은 표면이 눌리는 경우와 회전 시 가상 운반 목표점이 벽 반대편으로 넘어가는 경우를 분리했다. 최종 판정은 잡기 시작과 동일한 실제 캐릭터 시점→택배 중심 경로를 사용한다. 접촉 허용 수치를 늘리는 변경은 채택하지 않았다. 스프링 힘/무게/충돌은 유지한다. 실제 몸과 택배 사이의 벽, 깊은 침투, 접촉하지 않은 장애물 차단을 별도 검사한다.

## 남은 확인과 알려진 한계

- 재현된 계단 해제 원인은 수정했고 최종 반복 경로는 통과했다. 다른 물건/운반 각도/지연 조건의 모든 끼임이나 해제를 해결했다고 단정하지 않는다.
- 실제 2~4대 PC·외부망·패킷 손실/장시간/다른 GPU 성능, 사람이 3연속 코스를 운반하는 확인은 남았다. 직접 접속 기반의 기능 구현과 로컬 ENet 검증 완료를 출시용 온라인 검증 완료와 구분한다.
- 호스트 방 종료는 세션/기록 초기화, 참가자 퇴장은 진행 중 주문을 대기실에서 새로 준비하는 방식이다. 호스트 이전, Steam 초대/중계, 영구 진행 저장은 없다.
- 여러 도움 요청이 동시에 있으면 화면 위치 안내는 한 요청을 우선 표시한다. 고지연 연결에서는 호스트 응답을 따르는 이동 반응이 늦을 수 있다.
