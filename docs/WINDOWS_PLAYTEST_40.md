## 이번 빌드의 목표
사용자의 최신 지시에 따라 미세 버그보다 플레이 시스템과 흐름을 우선한다. 현재 빌라의 온라인 2인 모드에 주문 선택 → 두 사람 준비 → 배송 진행 → 주문 결과 → 다음 주문 준비를 연결했다.

## 플레이할 수 있는 주문
- 일반 배송: 201호·202호에 각각 1개, 총 2개.
- 다건 배송: 각 호수에 2개, 총 4개. 트럭 왕복 또는 목적지 분담을 선택한다.
- 공동 운반: 각 호수에 대형 45kg 택배 1개. 두 사람이 같은 상자를 함께 잡아 운반한다. 기존 Kenney 택배 에셋을 확대하고 실제 충돌 크기와 중량을 맞췄다. 무게는 첫 플레이를 위한 조정값이다.

호스트만 대기실에서 주문을 선택한다. 주문을 바꾸면 양쪽 준비가 초기화되고 이전 주문에 대한 늦은 준비 요청은 거부된다. 플레이 중 주문은 바꿀 수 없다. 대기실 안내와 실제 택배 수, 호수별 진행, 완료 판정은 같은 주문 목표를 사용한다. 복구는 완료한 배송을 유지하고 미배송 상자를 되돌린다.

배송 중 호스트 기준 경과 시간을 표시하고 결과에 주문 이름·총 배송 수·시간·호수별 배송 기록을 표시한다. 결과 시간은 고정되며 다음 주문은 대기실에서 선택한다. 같은 주문을 바로 재시작할 수도 있다. 제한 시간 실패, 별점, 경제 보상은 추가하지 않았다. 싱글/분할 화면은 기존 배송 구성을 유지하며 이번 주문 선택은 온라인 대기실 기능이다.

프로토콜 40: 양쪽 모두 빌드 40을 사용해야 한다. 이전 빌드와 혼용하지 않는다. commit/push 없음.

## 검증과 사용자 확인
신규 주문 전용 검사는 실제 대기실에서 다건/공동 운반 주문을 선택하고 준비·시작·결과·다음 주문으로 전환한다. 이 전용 검사는 일반 주문의 계단 운반 경로를 실행하지 않는다. 다건 배송은 부분 완료와 복구 유지, 총 4개 완료를 확인한다. 공동 운반은 중량/크기 구성과 두 사람의 실제 공동 잡기·들기를 확인한다. 추가 주문의 최종 목적지 배송은 fixture이므로 다건 4개 전체 수동 운반 및 대형 택배의 계단 전 구간 운반은 사용자 확인 대상이다.

우선 플레이: 다건 배송을 함께 완료하고 다음 주문으로 공동 운반을 선택해 본다. 작업 분담이 생기는지, 무거운 상자를 함께 들 때 재미와 진행 흐름이 자연스러운지 피드백을 받는다. 미세한 물리·시각 버그는 모아서 후속 수정한다. 외부망·장시간 플레이는 미검증이다.

## 원인과 변경
빌드 39의 수평 시점 운반 해제를 조사했다. 기존 0.8 전진 입력은 이번 소스 진단에서 연속 4회 배송을 통과했지만, 일반 키보드 걷기와 같은 1.0 입력에서는 BLOCKED 해제를 재현했다. 해제 광선의 종점은 계단 하부 충돌면 z=14.5 안쪽 z=14.54407로 약 4.4cm 겹쳐 있었다. 잡기 표면의 작은 물리 접촉 겹침까지 정적 장애물 차단으로 집계하던 판정을 보완했다.

GrabbableBody는 광선이 맞은 충돌체가 현재 물리 접촉 목록에 있고 잡기 지점의 면 법선 방향 침투가 6cm 이내일 때만 접촉 오차로 취급한다. 접촉하지 않은 장애물, 깊은 벽 차단, 거리 초과 해제는 유지한다. 힘·질량·최대 거리·충돌 레이어·계단 및 난간 구조는 변경하지 않는다. 판정 보완은 싱글/분할/온라인의 공통 운반 코드에 적용된다.

이 접촉 보완 자체는 패킷 변경이 없다. 최종 주문 시스템의 프로토콜은 40이다.

## 검증 구성
실제 RigidBody와 StaticBody를 접촉시키는 회귀 검사를 추가했다. 작은 접촉 겹침 유지, 깊은 벽 차단, 접촉 없는 광선 종점 차단, 두 잡기 연결 중 벽에 가려진 연결만 BLOCKED 사유로 해제를 검사한다.

온라인 자동 경로를 수평 시점 0 rad, 전진 입력 1.0, 회전 단계 0.04 rad로 복원·강화했다. 들어 올리기나 저속 운반으로 통과시키지 않는다. Run-OnlineTest.ps1에 -RepeatRoutes를 추가해 -RepeatRounds 횟수만큼 202호를 합성 입력으로 실제 운반한다. 201호 배송은 fixture이고, 사람의 수동 플레이와 외부 인터넷 시험은 아니다.

재현: tools/Run-OnlineTest.ps1 -Visual -RepeatRounds 3 -RepeatRoutes -RunTag <새 폴더>. 일반 회귀는 tools/Run-Godot.ps1 -Mode BuildVisual. 포트를 공유하므로 순차 실행한다.

## 중간 진단
Diagnostic(headless)은 배송 경로는 성공했으나 렌더링 시점의 동료 표식 및 마우스 캡처 검사 2개 실패로 전체 통과가 아니다. DiagnosticVisual과 DiagnosticRepeat는 수정 전 수평 0.8 경로 통과. DiagnosticFullWalk는 1.0 경로에서 차단 해제 재현 후 배송/로비 후속 검사가 실패했다. 로그를 보존한다. 접촉 전용 검사 첫 시도의 비접촉 장애물 배치가 광선 시작점과 겹쳐 해당 fixture를 분리한 후 재검증했다.

## 플레이 확인과 다음 작업
수평 시점으로 택배를 들고 현관 코너와 두 계단을 올라가 본다. 난간·계단에 가볍게 스쳤을 때의 잡기 유지와, 실제 벽 뒤로 가려졌을 때의 해제를 구분해 확인한다. 두 사람이 같은 택배를 잡는 상황도 확인한다. 모든 경로·시점·네트워크 지연에서 해제가 없다고 보장하는 수정은 아니다.

미세한 운반 조정은 최신 사용자 지시에 따라 후순위로 둔다. 기존 창 전환의 실제 Alt+Tab/최소화, 외부망·장시간 플레이 검증도 남아 있다.
